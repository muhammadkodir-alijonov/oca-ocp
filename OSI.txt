OSI (Open Systems Interconnection) Modeli Nima? 
------------------------------------------------
OSI modeli - bu tarmoq aloqasini 7 ta qatlamga bo'lib tushuntiruvchi 
standart model.  U 1984-yilda ISO (International Organization for 
Standardization) tomonidan yaratilgan.

================================================================================
        REQUEST SERVERGA QANDAY BORADI?  (BATAFSIL JARAYON)
================================================================================

Tasavvur qiling, siz brauzerda https://github.com saytini ochyapsiz: 


1-BOSQICH:  APPLICATION LAYER (Qatlam 7)
----------------------------------------
+----------------------------------------+
|  Brauzer: "github.com sahifasini ber!" |
|                                        |
|  HTTP Request yaratiladi:               |
|  GET / HTTP/1.1                        |
|  Host: github.com                      |
|  User-Agent: Chrome/120.0              |
|  Accept: text/html                     |
+----------------------------------------+

Nima bo'ladi: 
- Foydalanuvchi URL kiritadi
- Brauzer HTTP/HTTPS request yaratadi
- DNS so'rovi yuboriladi (github.com -> 140.82.121.4)


2-BOSQICH: PRESENTATION LAYER (Qatlam 6)
-----------------------------------------
+----------------------------------------+
|  Ma'lumotlar tayyorlanadi:             |
|                                        |
|  * HTTPS uchun TLS/SSL shifrlash       |
|  * Ma'lumotlar formati belgilanadi     |
|  * Siqish (Compression) qo'llanadi     |
|                                        |
|  "GET / HTTP/1.1..." -> [Shifrlangan]  |
+----------------------------------------+

Nima bo'ladi:
- SSL/TLS handshake (qo'l siqish) amalga oshiriladi
- Ma'lumotlar shifrlanadi
- Sertifikatlar tekshiriladi


3-BOSQICH:  SESSION LAYER (Qatlam 5)
------------------------------------
+----------------------------------------+
|  Sessiya o'rnatiladi:                  |
|                                        |
|  * Ulanish ochiladi                    |
|  * Session ID yaratiladi               |
|  * Sinxronizatsiya nuqtalari           |
|                                        |
|  Client <---- Session ----> Server     |
+----------------------------------------+

Nima bo'ladi:
- Client va Server o'rtasida sessiya ochiladi
- Aloqa boshqariladi
- Ulanish holati kuzatiladi


4-BOSQICH: TRANSPORT LAYER (Qatlam 4)
--------------------------------------
+----------------------------------------+
|  TCP Segmentatsiya:                    |
|                                        |
|  Ma'lumot -> [Segment 1][Segment 2]...  |
|                                        |
|  TCP Header qo'shiladi:                 |
|  +------------------------------+      |
|  | Source Port:  54321           |      |
|  | Dest Port: 443 (HTTPS)       |      |
|  | Sequence Number: 1000        |      |
|  | ACK Number: 0                |      |
|  | Flags: SYN                   |      |
|  +------------------------------+      |
+----------------------------------------+

TCP 3-Way Handshake: 

    Client                     Server
       |                          |
       | ---- SYN ------------->  |  (1.  Ulanish so'rovi)
       |                          |
       | <--- SYN-ACK ----------  |  (2. Tasdiqlash)
       |                          |
       | ---- ACK ------------->  |  (3. Ulanish o'rnatildi)
       |                          |
       | <----- DATA ---------->  |  (Ma'lumot almashish)


5-BOSQICH: NETWORK LAYER (Qatlam 3)
------------------------------------
+----------------------------------------+
|  IP Packet yaratiladi:                 |
|                                        |
|  +------------------------------+      |
|  | IP Header:                   |      |
|  | Source IP: 192.168.1.100     |      |
|  | Dest IP: 140.82.121.4        |      |
|  | TTL: 64                      |      |
|  | Protocol: TCP (6)            |      |
|  +------------------------------+      |
|  | [TCP Segment + Data]         |      |
|  +------------------------------+      |
+----------------------------------------+

Routing jarayoni: 

Sizning kompyuter -> Router 1 -> Router 2 -> ...  -> GitHub Server

Har bir routerda:
1. IP manzil tekshiriladi
2. Routing table'dan yo'l topiladi
3. Keyingi router'ga yo'naltiriladi


6-BOSQICH: DATA LINK LAYER (Qatlam 2)
--------------------------------------
+----------------------------------------+
|  Ethernet Frame yaratiladi:            |
|                                        |
|  +------------------------------+      |
|  | Preamble:  10101010...         |      |
|  | Dest MAC: AA:BB:CC: DD:EE: FF  |      |
|  | Source MAC:  11:22:33:44:55:66|      |
|  | Type: 0x0800 (IPv4)          |      |
|  +------------------------------+      |
|  | [IP Packet]                  |      |
|  +------------------------------+      |
|  | FCS (Error Check)            |      |
|  +------------------------------+      |
+----------------------------------------+

ARP Jarayoni (MAC manzil topish):

"Kim 192.168.1.1 (Gateway)?" -> Broadcast
Gateway: "Men!  MAC:  AA:BB:CC: DD:EE: FF"


7-BOSQICH: PHYSICAL LAYER (Qatlam 1)
-------------------------------------
+----------------------------------------+
|  Bitlar elektr signallariga aylanadi:  |
|                                        |
|  Frame -> 01101001 01110100...          |
|                                        |
|  ---+---+---+---+---+---+---+---       |
|   1 | 0 | 1 | 1 | 0 | 1 | 0 | 0        |
|  ---+---+---+---+---+---+---+---       |
|      |   |   |   |   |   |   |         |
|  Elektr/Optik signallar                |
+----------------------------------------+

Fizik muhit: 
- Ethernet kabeli (Cat5e, Cat6)
- Wi-Fi (radio to'lqinlar)
- Fiber optik (yorug'lik)

================================================================================
                        TCP vs UDP FARQI
================================================================================

+---------------------------------+---------------------------------+
|            TCP                  |             UDP                 |
+---------------------------------+---------------------------------+
| * Connection-oriented           | * Connectionless                |
| * Ishonchli (Reliable)          | * Ishonchsiz (Unreliable)       |
| * 3-way handshake               | * Handshake yo'q                |
| * Tartibni saqlaydi             | * Tartib kafolatlanmaydi        |
| * Sekinroq                      | * Tezroq                        |
| * HTTP, HTTPS, FTP, Email       | * DNS, Video streaming, Gaming  |
+---------------------------------+---------------------------------+
